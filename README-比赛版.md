# 稳厨 · 公开演示版

这是用于展示的早期演示，不是正式生产服务。首页提供三步使用地图，访客可以设置锅具、查找菜谱、查看烹饪步骤并按菜谱整理食材清单。

厨房昵称、头像和锅具保存在当前浏览器的签名 Cookie 中，不需要注册；请勿填写敏感信息。清除浏览器数据或更换浏览器后需要重新设置。步骤进度保存在当前浏览器的本地存储中。为保护公开演示，菜谱上传、修改、删除、讨论和投票功能暂不开放。

## 本地运行

需要 Python 3.10 或更新版本。

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 app.py
```

启动后访问 `http://127.0.0.1:5001`。首次使用可以从首页路线图设置现有锅具，再去找一道菜；设置锅具也可以跳过。

## 实时菜品分析

“上传一道菜”支持输入菜名或上传 JPG、PNG、GIF、WebP 图片。手机上可直接调用相机拍照，也可从相册选择；大图先在浏览器本机压缩，只有点击提交后才上传。启用实时分析前，在运行环境设置 `DEEPSEEK_API_KEY`；密钥只从服务端环境读取，不要写入源码、模板或浏览器代码。模型使用 DeepSeek `deepseek-flash`，参考稳厨自有菜谱、食材、工具和安全经验，以及同一锅具配置下经过人工复核的历史方案。

用户只看到一个输入流程。输入菜名时，页面在本地对照稳厨标准菜名和已生效别名进行文字联想，不发 AI 请求；选中匹配项且没有补充要求时，直接打开稳厨已验证方案，即使选了照片也不会上传该图。用户有个性化要求，或没有选中匹配项后提交，才进入 AI/历史方案流程；此时未命中完全匹配的已审核历史方案，才将输入送往 AI。当前演示库有 12 道稳厨自有菜，不包含“宫保鸡丁”；示例可用“可乐翅”联想到“可乐鸡翅”。

提交时页面要求同意查找历史方案、未命中时向 DeepSeek 发送输入，以及保存新生成的条件专属方案；若 AI 将输入叫法对应到已有标准菜，该叫法也会作为待审核别名保存。AI 不会自动新建标准菜谱记录；个性化分析仍可作为一条独立的条件专属历史方案保存，供完全相同条件复用。别名需单独通过复核后才参与联想；若来源分析方案尚待复核，别名随方案一起审，若目标方案已通过复核，别名进入独立队列。来源方案需更新或到期时，别名同步暂停；已审核的目标方案不会被同条件的 AI 别名校对覆盖。别名若与另一道菜冲突则拒绝覆盖。

只有“人工复核通过且未到期”的方案才会缓存命中；待复核记录不会复用。标准名或已审核别名先映射到同一个稳厨标准菜名，再计算请求指纹；未审核的别名不做语义猜测。其余条件仍必须严格一致：补充要求做 Unicode NFKC、大小写归一和空白折叠；锅具集合归一后排序；若上传照片，还必须是相同照片字节指纹。补充要求、锅具或照片不同，都不会硬套旧方案。知识库保存结构化分析结果、复核状态/意见及时间、命中计数和审核后的菜名别名；原图和原始补充文字不入库，请求与锅具指纹使用 `WENCHU_KNOWLEDGE_HASH_KEY` 或稳定的 `WENCHU_SECRET_KEY` 做 HMAC。新 AI 结果需人工复核后才可供相同条件的访客复用；建议每周整理队列，已通过记录默认 7 天后重新到期，并暂停缓存命中直到再次通过。可用 `WENCHU_KNOWLEDGE_REVIEW_DAYS` 调整复核周期（最少 7 天）。内部复核队列必须设置 `WENCHU_REVIEW_TOKEN` 才能查看和操作。图片上限为 4 MB，并限制每个浏览器每小时 3 次、每个服务进程每小时 15 次真实 AI 分析，另有全站每天 200 次上限。每日上限按 UTC 日期切换，发出请求前就预占额度，因此失败请求也计入；历史缓存命中不会调用 AI 或占用额度。可用 `WENCHU_ANALYSIS_DAILY_LIMIT` 调整上限、用 `WENCHU_ANALYSIS_QUOTA_DB` 指定额度 SQLite 文件。知识记录默认写入独立的 `dish_knowledge.sqlite3`，可用 `WENCHU_KNOWLEDGE_DB` 指定路径。SQLite 文件可在同一服务实例的 Gunicorn workers 间共享，但 Render 免费服务的本地文件会在替换或重新部署时丢失，多实例也不会自动共用该文件；正式生产环境应换成共享、持久化的数据库，并配置访问控制和适当的数据保护措施。

成本粗估（按 2026-11-18 查到的 [DeepSeek 官方价格表](https://api-docs.deepseek.com/quick_start/pricing) 重算）：应用使用 `deepseek-flash`（官方当前版本 DeepSeek-V4.1-Flash-1017）。沿用每次约 2,500 个文字输入 token、最多 1,800 个输出 token，假设输入缓存未命中；新价格为输入峰时 $0.30/百万 token、非峰时 $0.15/百万 token，输出峰时 $1.20/百万 token、非峰时 $0.60/百万 token。全站每日 200 次都打满时，纯文字分析约为峰时 **$0.58/天（$17.46/30天）**、非峰时 **$0.29/天（$8.73/30天）**。若每次都带图，按官方单图最多约 1,024 个额外输入 token，约为峰时 **$0.64/天（$19.30/30天）**、非峰时 **$0.32/天（$9.65/30天）**。这是按输出上限与图片 token 上限估算的保守数；缓存命中会更便宜，历史方案复用不调用 AI、也不占用每日分析额度。实际费用以 API 返回的 token 用量为准；token 换算规则见 [官方说明](https://api-docs.deepseek.com/quick_start/token_usage)，图片 token 说明见 [视觉输入文档](https://api-docs.deepseek.com/guides/vision)。

## 演示数据与使用边界

随包菜谱数据库是隔离后的演示副本，只包含 12 道菜、61 个烹饪步骤和分类数据，不含个人厨房资料或历史提问。访客的厨房设置在各自浏览器中保存，不写入共享菜谱库；经用户同意保存的结构化方案写入独立知识 SQLite 文件。

Render 免费 Web 服务空闲 15 分钟后会休眠，重新访问约需一分钟唤醒；服务可能因免费额度而暂停。本机文件的改动会在重启、休眠或重新部署时丢失。此演示不适合作为正式生产系统。Render 配置会生成稳定的会话密钥，但菜谱数据仍只是随版本发布的演示副本。

“新手配齐”中的品牌和店铺仅为合作设想示例，并未接入真实商品链接、价格或下单。锅具匹配是演示级关键词判断，不能替代用户检查。
